# ردیابی اجرای پروژه ERP

این فایل دفتر ثبت شواهد اجرایی است؛ فایل `erp-project.json` همچنان منبع داده گانت است. هیچ وضعیت «تکمیل‌شده»ای صرفاً به‌دلیل وجود کد، Issue یا اجرای workflow ثبت نمی‌شود.

## وضعیت بررسی اولیه — 2026-10-28

- مخزن: [pasoooir/Erp](https://github.com/pasoooir/Erp)
- شاخه مبنا: `main`
- آخرین commit بررسی‌شده در این مأموریت: `d28965723a99e14df5dfd3e68c1d77dd68d0632e` — مستندات قرارداد اجرا و ردیابی.
- گانت: `erp-project.json`، نسخه schema برابر `1.0.0`، ساختار شش‌سطحی و تعدادهای مورد انتظار 24/72/144/576/2304/4608.
- داشبورد: `Gonchar.html` داده را با `fetch('./erp-project.json')` می‌خواند؛ داشبورد فقط‌خواندنی است و هنوز API ثبت تغییرات ندارد.
- README می‌گوید همه درصدها صفرند تا شواهد واقعی ثبت شود.
- در ریشه، `package.json`، `index.html` و `docs/PROJECT_EXECUTION_TRACKER.md` در مسیرهای بررسی‌شده پیدا نشدند. مسیر انتشار Pages و ساختار مخزن باید با فهرست فایل‌های GitHub تأیید شوند؛ خطای 404 در مسیرهای بالا به‌تنهایی ثابت نمی‌کند که هیچ کد دیگری وجود ندارد.
- GitHub Actions: آخرین run قابل مشاهده برای Pages در زمان بررسی موفق بود؛ این فقط موفقیت انتشار Pages است، نه آزمون ERP یا صحت منطق گانت.
- اتصال Cloudflare در این نشست به هویت `pasooo.ir@gmail.com` پاسخ داد؛ این پاسخ به‌تنهایی اثبات دسترسی D1/Workers یا اجرای موفق workflow گیت‌هاب نیست.
- PR موجود: [#1 — Add Cloudflare D1 connectivity smoke test](https://github.com/pasoooir/Erp/pull/1). توضیحات PR می‌گوید آزمون دستی GitHub Actions هنوز باید جداگانه اجرا شود.

## محدودیت‌های ایمنی

این tracker مجوز انتشار production، ادغام در `main`، مهاجرت دیتابیس زنده، تغییر secrets یا حذف/بازنویسی داده واقعی نیست. این تغییرات در این مأموریت انجام نمی‌شوند. درصدها تنها پس از دریافت شواهد قابل بازبینی به‌روزرسانی می‌شوند.
