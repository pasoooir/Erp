# پایه عملیاتی ERP: احراز هویت، کاربران و ساختار سازمانی

این شاخه نخستین قابلیت عمودی قابل اجرا را اضافه می‌کند. کد در شاخه PR #3 و محیط CI محلی آزمایش شده؛ هنوز به Cloudflare راه‌دور منتشر نشده و Production نیست.

## قابلیت‌های پیاده‌سازی‌شده

- Worker API برای health، وضعیت bootstrap، ورود/خروج، هویت جاری، ساختار سازمانی و مدیریت کاربران.
- دو migration افزایشی:
  - `0001_erp_foundation.sql`: کاربران، نقش‌ها، نشست‌ها، تلاش‌های ورود، واحدهای سازمانی و رویدادهای ممیزی.
  - `0002_scoped_rbac.sql`: مجوزها، نگاشت نقش به مجوز و محدوده‌های سازمانی کاربران.
- bootstrap یک‌باره مدیر اولیه با Secret سمت سرور؛ رمز عبور با PBKDF2-HMAC-SHA256 و salt تصادفی هش می‌شود.
- نشست تصادفی ۲۵۶ بیتی؛ فقط SHA-256 توکن نشست در D1 ذخیره می‌شود. Cookie دارای HttpOnly، Secure، SameSite=Strict و Max-Age است.
- محدودسازی تلاش‌های ناموفق ورود، کنترل مبدأ، اعتبارسنجی payload، محدودیت اندازه body و ثبت ممیزی.
- ساختار سازمانی: ایجاد، فهرست، ویرایش نام/والد، فعال‌سازی/غیرفعال‌سازی، جلوگیری از چرخه والد و جلوگیری از غیرفعال‌سازی والد دارای فرزند فعال.
- مدیریت کاربران از UI مدیر: ایجاد کاربر، تعیین نقش و محدوده، فهرست کاربران با نام محدوده‌های قابل‌خواندن، فعال‌سازی/غیرفعال‌سازی. غیرفعال‌سازی کاربر همه نشست‌های او را revoke می‌کند.
- رابط فارسی RTL واکنش‌گرا برای ورود، bootstrap، ساختار سازمانی و مدیریت کاربر.

## نقش‌ها و محدوده‌ها

- `admin`: مدیر سراسری با دسترسی کامل.
- `org_manager`: خواندن/ایجاد/ویرایش/تغییر وضعیت در محدوده‌های سازمانی اختصاص‌یافته و زیرمجموعه‌های آن‌ها.
- `operator` و `reader`: فقط خواندن در محدوده‌های اختصاص‌یافته.
- نقش‌ها از `role_permissions` بررسی می‌شوند؛ scope با recursive CTE در سمت سرور اعمال می‌شود.
- کاربر غیرمدیر بدون scope مجاز نیست. ایجاد شرکت ریشه و مدیریت کاربران فقط برای admin مجاز است.
- جابه‌جایی واحد به بیرون از scope رد می‌شود. فهرست کاربران فقط برای admin قابل دسترسی است.

## قرارداد API

- `POST /api/v1/auth/bootstrap`: ایجاد یک‌باره نخستین مدیر با `X-Bootstrap-Secret`، `email`، `display_name` و `password`.
- `POST /api/v1/auth/login`, `POST /api/v1/auth/logout`, `GET /api/v1/auth/me`.
- `GET /api/v1/org-units`: برای admin همه واحدها؛ برای نقش‌های محدودشده فقط scope و زیرمجموعه‌ها.
- `POST /api/v1/org-units`: ایجاد واحد؛ نقش‌های محدودشده فقط زیر واحدی که در scope آن هستند.
- `PATCH /api/v1/org-units/{id}`: تغییر نام/والد؛ جلوگیری از چرخه و انتقال خارج از scope.
- `POST /api/v1/org-units/{id}/activate` و `/deactivate`: تغییر وضعیت با کنترل سلسله‌مراتب و audit.
- `GET /api/v1/users`, `POST /api/v1/users`: فهرست/ایجاد کاربر فقط برای admin.
- `POST /api/v1/users/{id}/activate` و `/deactivate`: تغییر وضعیت کاربر؛ جلوگیری از غیرفعال‌سازی حساب جاری و revoke نشست‌های کاربر غیرفعال‌شده.
- `GET /api/health`: وضعیت Worker و اتصال D1.

## محیط توسعه و آزمون

1. Node.js 22 یا جدیدتر.
2. برای توسعه راه‌دور، یک D1 اختصاصی بساز؛ `erp-connectivity-test-20261028` فقط دیتابیس تست اتصال است و برای داده ERP استفاده نمی‌شود.
3. `wrangler.toml` در CI از D1 محلی استفاده می‌کند؛ شناسه آن مجوزی برای مهاجرت راه‌دور نیست.
4. Secret محلی `BOOTSTRAP_SECRET` را در `.dev.vars` تعریف کن؛ آن را در کد/Git ذخیره نکن.
5. `npm test` و `npm run check` برای آزمون‌های واحد/قرارداد؛ CI همچنین migrationهای D1 محلی و smoke واقعی Worker/Chromium را اجرا می‌کند.
